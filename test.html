Comment créer une bibliothèque

Guide étape par étape pour créer votre propre bibliothèque MicroBlocks (par Turgut Guneysu)

Qu'est-ce qu'une bibliothèque ?

Lorsque nous écrivons du code et que nous nous surprenons à répéter un ensemble d'instructions ou certaines procédures, il peut être utile de les coder une seule fois et de convertir le tout en Bibliothèque. Ainsi, nous et les autres pourrons l'utiliser plus tard en chargeant simplement la bibliothèque dans nos programmes.

Une bibliothèque est un ensemble de code, généralement axé sur l'activation d'un composant, d'un périphérique ou d'une fonctionnalité spécifique. Ce qui distingue une bibliothèque d'un programme, c'est qu'elle constitue un composant ou une brique de construction qui sera utilisée dans un programme, mais qu'elle ne forme pas un programme complet en soi.

Les bibliothèques peuvent être créées soit à l'aide de l'IDE (environnement de développement) de MicroBlocks, soit en écrivant du code dans le langage d'origine utilisé pour créer l'IDE à l'origine.

Qu'est-ce qui fait une bonne bibliothèque ?

Une bonne bibliothèque doit :

  • Avoir un objectif précis.
  • Mettre en œuvre une interface utilisateur propre.
  • Ne pas inclure de choses inutiles.

Pour atteindre ces objectifs, un peu de planification et de réflexion s'impose.

1. Objectif (Purpose)

La bibliothèque doit remplir une fonction spécifique pour obtenir un résultat défini. Pour y parvenir, il faut réduire la tâche à sa fonctionnalité la plus importante et l'isoler dans la bibliothèque. Qu'il s'agisse de piloter un matériel ou d'effectuer une manipulation de données, l'objectif doit être clair et concis.

2. Interface utilisateur (User Interface)

C'est la partie la plus visible et la plus importante. Les utilisateurs interagiront avec notre code via l'interface utilisateur et jugeront de sa simplicité et de sa clarté à travers elle.

Pour l'organiser, il faut identifier :

  • Les entrées (Inputs) : toutes les données dont la bibliothèque a besoin de la part de l'utilisateur pour fonctionner (organisées en paramètres).
  • Les sorties (Outputs) : ce que la bibliothèque renvoie ou modifie physiquement en retour (toutes les fonctions ne renvoient pas forcément une valeur).

3. Pertinence (Relevance)

La bibliothèque ne doit pas faire de choses superflues. Souvent, le code d'une bibliothèque naît de blocs personnalisés créés pour un besoin ponctuel dans un projet. Il est facile de se laisser emporter et d'ajouter de plus en plus de fonctionnalités, ce qui alourdit inutilement le code final. Il est préférable de cibler strictement l'objectif initial.

Remarque : Les blocs d'une bibliothèque MicroBlocks ne doivent pas dépasser 1000 octets.

Passons à la pratique : Écrivons-en une !

Pour faire simple, développons une bibliothèque simple en utilisant l'IDE MicroBlocks.

Objectif

Nous voulons améliorer les capacités de messagerie radio par défaut des micro:bit (limitées à 17 octets) pour permettre d'envoyer des messages de n'importe quelle taille, de tout type (chaînes de caractères, nombres, listes, booléens). En option, si le message dépasse 17 octets, nous afficherons le nombre de tampons (buffers) sur la matrice LED de l'appareil.

Interface

  • Nom du bloc : RadioMsg
  • Paramètre de message : msg (type nombre/chaîne).
  • Paramètre optionnel d'affichage : ShowBuf (interrupteur booléen bufYN).

Blocs de code

Le programme gère les étapes suivantes :

  1. Variables locales :
    • Delay pour espacer les transmissions radio et ne pas saturer le réseau.
    • radMsgSize pour définir la taille maximale de chaque morceau (17 octets).
    • msgOut pour stocker la longueur du message.
  2. Conversion du type : Le message est converti au format texte (les listes deviennent des chaînes séparées par des virgules, les booléens deviennent "true/false", etc.) à l'aide du bloc de jointure de listes.
  3. Découpage et Envoi :
    • Si le message fait 17 octets ou moins, il est envoyé directement.
    • S'il est plus grand, une boucle s'occupe d'envoyer chaque morceau (msgPart) un par un en s'appuyant sur le compteur buff#.
    • Si le paramètre ShowBuf est activé, la progression s'affiche sur la matrice LED.
  4. Nettoyage : L'affichage de l'appareil est effacé à la fin.

Enregistrez votre programme source sous le nom : RadioMsg.ubp.

Conversion au format de bibliothèque (.ubl)

Les modules de bibliothèque utilisent l'extension .ubl.

  1. Activez l'option « Afficher les blocs avancés » (Show advanced blocks) dans le menu Paramètres (Settings).
  2. Rendez-vous dans le menu Fichier (File) et sélectionnez « Exporter les fonctions en tant que bibliothèque » (Export functions as library).
  3. Entrez le nom de votre bibliothèque : RadioMsg et cliquez sur OK.
  4. Enregistrez le fichier sur votre ordinateur. Il sera sauvegardé sous le nom RadioMsg.ubl.

Vous pouvez désormais aller dans la section Bibliothèques+ de l'IDE MicroBlocks, charger votre fichier .ubl, et l'utiliser dans n'importe quel autre programme !

Gestion des versions (Versioning)

Travailler avec des scripts destinés à devenir des bibliothèques implique quelques bonnes pratiques :

  • Fichier source : Continuez de travailler et de tester vos modifications dans le fichier source d'origine RadioMsg.ubp.
  • Exportation des versions :

    Lorsque vous exportez, modifiez éventuellement le nom pour y inclure un numéro de version (par exemple : RadioMsg-v01.ubl).

    Vous obtiendrez ainsi une structure propre :

    • Fichier d'origine : RadioMsg.ubp
    • Versions de bibliothèque : RadioMsg.ubl, RadioMsg-v01.ubl, etc.

Méthode alternative pour ajouter des blocs directement :

  1. Glissez-déposez le fichier .ubl de la bibliothèque dans un nouveau projet MicroBlocks.
  2. Créez et testez vos nouveaux blocs dans la catégorie « Mes blocs » (My Blocks).
  3. Faites un clic droit sur le nouveau bloc personnalisé, sélectionnez « Afficher la définition du bloc », puis cliquez sur « Ajouter à la bibliothèque » (Add to library) et choisissez le nom de votre bibliothèque chargée.
  4. Ré-exportez la bibliothèque avec un nouveau numéro de version.
